# 游戏版本更新影响基线 v1

## 回答的问题

本报告比较“当前游戏版本”和管理目录中最近的旧冻结版：优先按游戏版本号，其次按 Steam Build ID。它不把普通版本号或 Build 变化直接判为 MOD 不兼容，只寻找当前分析范围与游戏更新之间的实际交集。

## 三条证据链

1. **PZ 脚本实体**：递归读取两版 `media/scripts`，按 `module + 完整实体头` 建立索引。只有原版实体内容更改或移除，并且当前 MOD 也定义同一个键时，才报告受影响。
2. **原版同路径目标**：只检查当前 MOD 有效文件中也存在于至少一个原版的路径，逐文件比较两版 SHA-256。只有 MOD 文件与旧版原版 SHA-256 完全相同且新版已变化时，才确认它是旧版整文件副本；其他同路径变化保留为待验证，避免把翻译、Lua 或特殊索引的合并行为误报成冲突。
3. **Java 游戏接口**：只检查当前 MOD JAR 常量池真实引用到的 `zombie/*` Class，逐 Class 比较两版 `projectzomboid.jar`。新版移除是警告；内容变化是待验证，因为字节变化不能证明 API 已破坏。

## 严重度边界

- **警告**：MOD 同键定义命中原版实体变化、MOD 文件是旧版原版的精确副本、引用的游戏 Class 被移除。
- **待验证**：同路径原版文件变化但不是精确旧副本、引用 Class 内容变化、任一输入未完整解析、没有旧冻结版基线。
- **通过**：已完成的对应检查没有发现交集。
- 本阶段不产生“阻断”。静态版本差异本身不足以证明游戏一定无法启动。

## 完整性与只读边界

- 冻结版候选必须低于当前版本且保留 `projectzomboid.jar`。
- 脚本解析失败的整个文件不会进入实体差异索引，报告标为 `partial`，不会用缺失数据宣告通过。
- 分析只读取游戏、冻结版和 MOD 文件；报告写入 `reports/version-impact`，不修改源内容。
- 反射、动态类名、Lua 运行分支、Mixin 实际应用和游戏行为仍需要启动日志与复制存档测试。
