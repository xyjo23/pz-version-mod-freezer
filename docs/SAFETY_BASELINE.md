# 阶段 0：写入安全基线

本文件记录启动器允许写入的位置、必须满足的归属条件，以及回归测试证据。目标是让版本切换、迁移、共享包安装和分析报告都不能越过用户明确选择的版本库边界。

## 核心不变量

1. 受管版本只能位于其登记管理目录的 `frozen/<版本目录>` 下。
2. 写入前同时检查规范化路径与真实磁盘路径，目录联接或符号链接不能把写入引向库外。
3. 切换版本只更新该版本所属库的 `current-freeze.json`，不能更新之前选中的库。
4. 外部导入版本按只读来源处理：激活时不改写它的 `metadata/freeze.json`，也不写任何管理库指针。
5. 外部元数据中的旧绝对报告、备份和清单路径不可信；运行时统一使用外部版本目录内的 `reports`、`backups` 和 `manifests`。
6. 迁移预览后再次核对当前管理目录；若目录已经改变，必须重新预览，不能沿用旧目标。
7. 迁移完成后按完整绝对路径激活新版本，不能用可能重名的目录名查找。
8. 关键 JSON 使用同目录临时文件和原子替换；内容不变时不写盘；替换中断时保留并恢复回滚文件。
9. `current-freeze.json` 发生真实变化前保留 `current-freeze.json.launcher-backup`。
10. 共享包安装状态只能通过当前受管版本的归属检查后写入，不能自行拼接管理目录。

## 写入位置分级

| 类别 | 允许位置 | 保护方式 |
| --- | --- | --- |
| 启动器设置与登记册 | Electron `userData` | 串行原子 JSON 写入 |
| 受管版本元数据 | `<manager>/frozen/<version>/metadata` | 登记归属、真实路径归属、原子写入 |
| 旧版活动指针 | `<owner-manager>/current-freeze.json` | 所属库校验、变更备份、原子写入 |
| 迁移中的文件 | `<manager>/.staging` | 事务标记、完成后同卷重命名提交 |
| 中断迁移诊断 | `<manager>/incomplete` | 只移动未提交暂存目录，不删除来源 |
| 存档保护快照 | `<manager>/save-backups` | 新建目录，不覆盖原存档 |
| 完整性、兼容性与启动报告 | 当前版本自身 `reports`；Steam 使用管理目录或 `userData` | 路径规范化、原子写入 |
| 共享清单导出 | 用户在保存对话框中选择的位置 | 原子文件写入 |

## 明确禁止

- 不直接改写 Steam 游戏目录或 Workshop 下载目录。
- 不在版本切换时复制、删除或覆盖游戏文件。
- 不把外部导入目录自动“接管”为受管版本。
- 不跟随库内目录联接把受管写入导向库外。
- 不在迁移失败时删除已复制的数据；失败内容进入 `incomplete` 供诊断。

## 自动化证据

- `pnpm test:safety`：路径边界、真实路径逃逸、原子替换、幂等写入、并发串行与中断恢复。
- `pnpm test:activation:e2e`：多版本库切换、错误库指针保持不变、外部元数据只读。
- `pnpm test:import:e2e`：外部版本路径运行时规范化、重复导入和无效目录处理。
- `pnpm test:migration:e2e`：全量/快速迁移、磁盘不足、锁文件、重复目标、依赖缺失和中断恢复。
- `pnpm test:migration:interrupt`：提交前强制终止后不暴露半成品，原活动版本保持不变。
- `pnpm test:share:e2e`：共享包重建、篡改阻断、隔离状态和安装后指纹复核。

阶段 0 完成条件：以上测试、`pnpm test:qa`、生产构建全部通过，且真实正式版本只做只读核对。
