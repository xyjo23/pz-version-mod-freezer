# 架构说明

## 目标

PZ Version & Mod Freezer 将一个可玩的 Project Zomboid 环境保存为独立快照。Steam 原版继续正常更新，快照中的游戏、MOD 和存档保持在创建时的状态。

## 组件

- `PZ-Freezer.ps1`：WPF 图形界面、自动检测、后台任务和多快照切换。
- `tools/PZ-Freeze-Manager.ps1`：复制、启动、校验、备份和恢复核心。
- `tools/Analyze-PZMods.ps1`：B41/B42 版本目录选择、Mod ID、依赖和存档启用列表分析。

## 数据模型

每个 `profiles/<版本标签>` 都是独立快照：

- `game`：完整游戏与自带 Java。
- `cache`：独立缓存、本地化后的 Workshop MOD、配置和存档。
- `manifests`：游戏与 MOD 的 SHA-256 基线。
- `metadata`：来源、BuildID、Mod ID、Workshop ID 和复制映射。
- `reports`：创建、隔离、校验和内存配置报告。
- `backups`：独立存档 ZIP。

根目录的 `current-freeze.json` 只负责指出当前快照，不包含游戏文件。

## 隔离方式

冻结版使用：

```text
ProjectZomboid64.exe -nosteam -cachedir=<快照的 cache 目录>
```

Workshop 内容复制为 `cache/mods` 下的本地 MOD。核心内容使用真实文件复制，不使用符号链接、目录联接或硬链接。

## 创建事务

1. 确认游戏没有运行。
2. 检测 Steam、游戏、Workshop、缓存和版本。
3. 检查链接、磁盘空间、Mod ID 和依赖。
4. 复制游戏和缓存。
5. 把 Workshop MOD 转为快照内本地 MOD。
6. 对来源和副本计算 SHA-256 并比较。
7. 只对冻结副本应用安全 Java 内存上限。
8. 生成最终哈希基线、配置和启动器；冻结副本本身已包含创建时的存档，不再额外制作重复 ZIP。
9. 完成静态隔离验证后才宣布成功。

## 可变与不可变内容

游戏和冻结 MOD 属于完整性基线。存档、配置和日志允许正常变化。JVM 诊断文件 `hs_err_pid*.log` 与 `replay_pid*.log` 不参与完整性比较。

## 增量迁移事务

增量迁移面向已经存在的冻结快照：

1. 快速扫描 Steam 游戏与 Workshop，只比较相对路径、存在性和文件大小。
2. 游戏版本与 BuildID 完全兼容时，补齐缺失的游戏文件；不覆盖已有文件。
3. 按有效 `mod.info` 的 Mod ID 比较，只复制目标中缺少的 Workshop MOD。
4. 阻止重复 Mod ID、缺失依赖和不明确的来源。
5. 备份清单、MOD 映射和快照配置；存档 ZIP 由用户通过独立的“备份存档”操作创建。
6. 仅对新增文件计算 SHA-256，并增量更新游戏/MOD 基线。
7. 在 `migrations/<时间>` 保存新增文件、哈希和元数据备份。

回迁会先重新计算本次新增文件的哈希。任何文件发生后续变化时，整个回迁在删除前停止；没有冲突时才删除本次新增文件并恢复迁移前元数据。

## 自动迁移目标判定

- 选择目录本身不再要求目录中已有冻结配置。
- 检测到 `metadata/freeze.json` 或可唯一解析的当前冻结配置时，采用增量迁移。
- 目标目录为空时，以该目录本身作为 `FreezeRoot` 执行首次完整迁移。
- 目标非空但无法解析为冻结版时停止，绝不自动覆盖其中内容。

## 多版本库

- 主界面按职责拆分为默认“版本”标签页和次级“迁移冻结工具”标签页。
- 版本页负责添加、浏览、切换、校验和启动；迁移页负责创建或更新冻结版本及备份存档。
- 两个工作流共用底部运行状态与日志区，以便后端动作保持一致的进度反馈。
- UI 使用顶部深色导航和启动器式主操作区；没有引入第三方 UI 框架、代码或图片素材。
- `version-library.json` 只保存用户添加的本地扫描根目录，不复制游戏数据。
- Steam 原版是启动时从 AppID 108600 动态生成的系统项目，不持久化到版本库配置；检测失败时生成带错误原因的占位项目。
- Steam 项目通过 `steam://run/108600` 启动，通过 `steam://validate/108600` 请求 Steam 校验，不复用冻结版的 `-nosteam` 启动逻辑。
- 启动时扫描程序内 `profiles`、当前版本和已登记目录中的 `metadata/freeze.json`。
- 扫描深度限制为 6，并拒绝直接扫描磁盘根目录。
- 版本以实际 `FreezeRoot` 去重，移动后的完整版本目录按元数据文件当前位置重新定位。
- 健康检查覆盖 `ProjectZomboid64.exe`、独立 `cache` 和 `game.sha256.csv`。
- 启动或校验所选版本前，先更新 `current-freeze.json`，随后复用现有后端动作。
- 每个版本仍使用自己的游戏目录和 `cache`；本阶段不共享实体文件。

## 选择性存档备份

- GUI 枚举当前冻结缓存下的 `Saves/<模式>/<存档>`，由用户选择一个具体存档。
- 用户必须另外选择 ZIP 的外部保存目录。
- ZIP 完整保留所选存档内部的所有文件，因为地图分块、角色、车辆和 MOD 可能各自维护状态。
- ZIP 不包含其它存档、MOD 资源、日志、录像、Workshop 缓存和全局 UI/按键设置。
- 压缩时直接从存档写入 ZIP，不再先复制到临时 staging 目录。
- ZIP 内含 `backup-manifest.json`，旁边另存摘要 JSON 和 SHA-256。

## 安全原则

- 不修改 Steam manifest。
- 不修改原始游戏、Workshop 或原始存档。
- 不覆盖既有快照。
- 不在游戏运行时创建或恢复。
- 恢复操作默认解压到新目录，不覆盖当前存档。
