# MOD 中心与安全启用规划器

MOD 中心是当前 Steam 原版或冻结版本的 MOD 证据工作区。浏览、搜索、筛选、查看详情和重新建立数据库都是只读操作；只有进入“安全启用规划器”、生成通过校验的预览并再次确认后，启动器才会修改用户明确选择的存档或服务器清单。

## 页面回答的问题

- 当前版本实际识别了哪些 Workshop 与本地 MOD；
- 最近存档或唯一服务器上下文中，哪些 Mod ID 正在启用；
- B42 `common` 与版本目录最终选择了哪些生效层；
- 每个 MOD 声明了哪些必需依赖、互斥关系和加载顺序；
- 哪些 MOD 依赖当前选中的 MOD；
- 是否存在缺失依赖、已安装互斥项、重复 Mod ID 或无法解析的版本层；
- 有效内容包含哪些文件类型，是否存在 JAR、Class 或本地二进制；
- JAR 内包含多少 Class、使用哪个 Java 字节码范围、引用多少 PZ API，以及是否存在 Mixin/native/跨 MOD 同名类证据；
- 内容摘要、实际目录与证据是否完整。

## “启用”含义

“当前启用”必须来自明确上下文：最近修改的存档 `mods.txt`，或在没有存档时唯一可确认的服务器配置。没有唯一上下文时，页面不会猜测启用状态；已安装不等于已启用。

## 问题筛选

“有问题”筛选仅包含具有明确静态证据的条目：

- 必需 Mod ID 当前未安装；
- MOD 与其声明的互斥 Mod ID 在明确上下文中同时启用；
- 同一个 Mod ID 对应多个实际来源；
- B42 版本层或 Mod ID 无法解析；
- 文件不可读，或目录联接/符号链接因安全边界被跳过。

“含代码”不是冲突结论。它表示数据库发现 JAR、Class 或本地二进制，提醒用户这部分内容不能只按资源文件理解。

## 性能与数据边界

统一数据库会保存每个有效文件的 SHA-256，但界面进程只接收每个 MOD 的统计、关系和摘要，不接收全部文件清单。这样可以在大型 MOD 集合中保持搜索和切换详情的速度。

MOD 中心不会执行 Lua、Java 或本地二进制，也不会删除、下载或改写任何 MOD 文件。启用规划器只会更新所选上下文的 `mods.txt` 或服务器配置，并保留可撤销备份。

## 安全启用规划器

1. 明确选择一个存档或服务器上下文。规划器不会把多个上下文混在一起，也不会猜测目标。
2. 点击“编辑启用清单”，用列表右侧开关选择目标 Mod ID。此阶段只改变页面中的草稿。
3. 点击“生成安全预览”。规划器会重新运行兼容性分析，递归补齐必需依赖，并按依赖、`loadBefore` 与 `loadAfter` 关系计算稳定加载顺序。
4. 核对新增、停用、自动补齐和顺序变化。缺失依赖、重复 Mod ID、同时启用的互斥项、加载顺序循环、不可用的 B42 内容层、不满足或无法解析的版本范围、无法验证的游戏身份、证据不完整或不安全的目标文件都会阻止应用。
5. 只有点击“确认应用并保留撤销备份”才会写入。应用前会再次扫描；如果文件内容或分析结果已变化，旧预览令牌会失效，必须重新预览。

写入采用原子替换，并先生成 `Prepared` 收据与备份，成功后再记录 `Applied` 收据。页面中的“撤销上次清单变更”会先核对当前文件哈希；如果游戏、用户或其他工具已经继续修改该文件，撤销会拒绝覆盖，以免丢失后来改动。

规划器只管理 Mod ID 与 Workshop ID 清单，不安装缺失 MOD，不删除现有 MOD，也不会承诺脚本运行时的绝对兼容。静态检查通过后，仍应复制存档进行一次实际开档或进服验证。

## 与兼容性报告的分工

MOD 中心适合逐个查看内容与关系，并为一个明确上下文规划安全清单；兼容性报告负责对当前组合给出阻断、警告、待验证和通过结论。页面中的“查看兼容性报告”只负责跳转，不会自动应用任何修复。
