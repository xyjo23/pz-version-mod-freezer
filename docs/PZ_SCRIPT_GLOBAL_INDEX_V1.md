# PZ 脚本全局实体索引 V1

## 解决的问题

两个 MOD 可以使用完全不同的文件名，却在脚本中声明相同的 `module + item/model/vehicle/...`。仅比较相对路径会漏掉这种关系。全局索引读取当前分析范围内每个实际生效的 `media/scripts/*.txt`，以完整定义键建立反向所有者表。

索引单独保存到 `reports/script-definition-index/latest-<source>.json`，包含游戏身份、分析范围、定义所有者、语义 SHA-256、结构摘要和未解析证据。兼容性报告只引用索引摘要和需要处理的条目，避免界面装入数万条定义。

## 分类规则

- 不同路径、同一实体、内容不同：警告。物品字段、车辆模型、纹理或尺寸可能由加载顺序决定。
- 不同路径、同一实体、内容一致：通过。保留所有来源，但不重复报告风险。
- `model` 主要增加 `attachment`，或重复 `xuiSkin` 加入界面实体：待验证的扩展式组合，不混入普通覆盖警告。
- 文件无法完整解析：待验证，并从全局“通过”覆盖范围中排除。

扩展式分类同时参考当前 42.22.2 游戏 JAR：`ModelScript.Load` 与 `XuiSkinScript.Load` 会读取对应子块，且两个 `Load` 方法本身没有调用类中独立存在的 `reset`。这支持“可能组合”判断，但仍不足以替代实际加载顺序和运行结果。

## 安全边界

索引只读，不执行脚本，不修改 MOD。警告证明的是“同一实体存在不同静态定义”，不是证明某个作者有错。主 MOD、共享库和补丁常会有意复用实体；处理时必须结合作者说明、加载顺序、测试存档与 `console.txt`。
