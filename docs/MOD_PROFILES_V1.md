# MOD 配置档案 v1

MOD 配置档案用于保存一个明确游戏版本下，某个存档或服务器实际使用的 MOD 清单。它只记录配置和证据，不复制 MOD 文件，也不会自动下载 Workshop 内容。

## 捕获内容

- 游戏来源、版本、Build、revision 与游戏 JAR SHA-256；
- 存档或服务器上下文类型和名称；
- 有顺序的 Mod ID 与 Workshop ID；
- 捕获时统一 MOD 数据库的摘要与完整性状态；
- 配置档案自身的 SHA-256 摘要。

导出为 `.pzprofile` 时会移除本机存档或服务器配置的绝对路径，避免把本机目录信息传给别人。

## 应用流程

1. 用户在兼容性分析中选择目标存档或服务器；
2. 系统重新分析当前游戏和 MOD，比较游戏身份、目标格式、缺失项目与加载顺序；
3. 页面只展示差异，不立即写文件；
4. 用户明确确认后，系统再次分析并验证预览令牌；
5. 系统先复制原文件并写入 `Prepared` 收据，再原子更新目标文件；
6. 写后 SHA-256 符合预期，收据才会进入 `Applied` 状态。

预览后只要游戏身份、目标文件或清单发生变化，旧预览就失效，必须重新比较。

## 阻断规则

以下情况不会写入：

- 游戏版本、Build、revision 或 JAR SHA-256 不完全相同；
- 存档档案被用于服务器配置，或服务器档案被用于存档；
- 档案中的 Mod ID 或 Workshop ID 当前未安装；
- 目标文件不属于当前版本缓存目录；
- 目标、备份或恢复收据越出受管目录；
- 文件结构含糊，例如服务器配置出现重复 `Mods=` 项；
- 导入文件存在未知字段、非法 ID、重复 ID 或摘要不匹配。

## 文件改写边界

存档 `mods.txt` 只替换 `mods { ... }` 区块内的 `mod =` 行，保留 BOM、换行风格、注释、地图区块及其他内容。

服务器 `.ini` 只替换 `Mods=` 与 `WorkshopItems=`，其他设置保持不变。若同一键出现多次，系统拒绝猜测。

## 撤销规则

撤销只处理最近一次仍为 `Prepared` 或 `Applied` 的操作。系统会验证：

- 收据、目标和备份都在原有受管目录内；
- 备份 SHA-256 与写入前摘要一致；
- 目标仍等于写入后摘要。

如果用户或游戏在应用后又改过目标文件，系统不会直接覆盖，而是要求先人工核对。这样撤销不会抹掉之后产生的新配置。

## 当前边界

v1 管理的是启用清单与顺序，不修改 MOD 内容，不下载 Workshop，不执行 Lua、Java 或本地二进制，也不把兼容性报告中的“警告”解释成确定冲突。只有明确证据满足规则时才允许应用。
