# 统一 MOD 数据库 v1

兼容性分析会为当前版本重建一个本机 JSON 数据库。它是分析证据，不是游戏文件，也不会替代 Steam Workshop。

## 收录内容

- 游戏版本、Build、revision 和游戏 JAR 身份。
- Workshop ID、Mod ID、本地/Workshop 来源和当前是否启用。
- B42 可见版本目录、实际选中版本和 `common + 版本层`。
- `require`、`incompatible`、`loadModAfter`、`loadModBefore`。
- 每个实际生效普通文件的路径、大小、修改时间、类型和 SHA-256。
- common 被版本层覆盖的具体路径。
- JAR、Class 和 DLL/SO/DYLIB/EXE 清单。
- JAR 内每个 Class 的类名、SHA-256、字节码版本和 native 方法数量。
- JAR 对 Project Zomboid / Kahlua 类的静态引用、Mixin 框架痕迹和可推断目标。
- 游戏内置 Java 运行时版本、多版本 JAR 标记和跨 MOD 同名类来源索引。
- 重复 Mod ID、反向依赖和 Workshop ID 索引。
- 不可读文件、扫描期间变化的文件，以及被安全跳过的目录联接/符号链接。

## 完整与不完整

`complete` 表示所有已解析 MOD 的实际生效普通文件都取得了稳定 SHA-256，且没有跳过目录联接。

出现以下任一情况时标记为 `partial`：

- 没有可用于目标游戏版本的 B42 内容层；
- 缺少 Mod ID；
- 文件或目录不可读；
- 文件在扫描过程中持续变化；
- 发现目录联接或符号链接，系统为防止越界而没有跟随。

`partial` 不是“确认损坏”，但不能把数据库解释为完整覆盖。

## 摘要规则

数据库摘要使用 SHA-256，输入包括游戏身份、每个 MOD 的内容摘要、依赖、版本变体、启用状态和索引。只比较文件大小或修改时间不足以判定内容相同；即使攻击者或复制工具保留了这些元数据，文件内容变化仍会改变摘要。

## Java / JAR 静态证据

JAR 使用受限 ZIP 流读取：限制文件大小、条目数量、单个 Class 大小和总解压量，不把任何内容释放到磁盘，也不通过 JVM 加载类。Class 解析只读取结构与常量池，并为每个类计算独立 SHA-256。

跨 MOD 出现同名类时：

- 类哈希相同，只记录为重复打包的相同内容，不报冲突；
- 类哈希不同，报告为需要核对的类加载顺序证据，不直接断言哪个 MOD 有错；
- 只比较当前明确启用上下文中的 MOD，未启用 JAR 不会污染当前组合结论。

游戏目录 `jre64/release` 提供实际 Java 版本和可接受的 Class 上限。对多版本 JAR，只有基础类以及不高于当前 Java 版本的 `META-INF/versions/<N>` 层参与版本可用性判断；备用高版本层不会被误报为当前失败。

## 当前边界

静态 Class 证据不能证明反射、动态生成、类加载器顺序、Mixin 实际应用或运行时分支一定发生，也不能判断代码来源是否可信。分析器不会执行 Lua、Java 或本地代码；最终运行兼容性仍需结合受控启动和日志证据。
