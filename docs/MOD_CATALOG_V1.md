# 统一 MOD 数据库 v1

兼容性分析会为当前版本重建一个本机 JSON 数据库。它是分析证据，不是游戏文件，也不会替代 Steam Workshop。

## 收录内容

- 游戏版本、Build、revision 和游戏 JAR 身份。
- Workshop ID、Mod ID、本地/Workshop 来源和当前是否启用。
- B42 可见版本目录、实际选中版本和 `common + 版本层`。
- `require`、`incompatible`、`loadModAfter`、`loadModBefore`。
- 每个实际生效普通文件的路径、大小、修改时间、类型和 SHA-256。
- common 被版本层覆盖的具体路径。
- JAR、Class 和 DLL/SO/DYLIB/EXE 清单。
- 重复 Mod ID、反向依赖和 Workshop ID 索引。
- 不可读文件、扫描期间变化的文件，以及被安全跳过的目录联接/符号链接。

## 完整与不完整

`complete` 表示所有已解析 MOD 的实际生效普通文件都取得了稳定 SHA-256，且没有跳过目录联接。

出现以下任一情况时标记为 `partial`：

- 没有可用于目标游戏版本的 B42 内容层；
- 缺少 Mod ID；
- 文件或目录不可读；
- 文件在扫描过程中持续变化；
- 发现目录联接或符号链接，系统为防止越界而没有跟随。

`partial` 不是“确认损坏”，但不能把数据库解释为完整覆盖。

## 摘要规则

数据库摘要使用 SHA-256，输入包括游戏身份、每个 MOD 的内容摘要、依赖、版本变体、启用状态和索引。只比较文件大小或修改时间不足以判定内容相同；即使攻击者或复制工具保留了这些元数据，文件内容变化仍会改变摘要。

## 当前边界

v1 只登记 JAR、Class 和本地二进制及其内容哈希，不宣称已经理解它们的内部依赖。Java 字节码引用、Mixin/注解目标和类级冲突属于后续解析阶段。v1 同样不会执行 Lua、Java 或本地代码。
